Step 5 — Host Frontend on S3

🎯 What are we doing?

We are deploying our frontend (HTML/CSS/JS) to AWS S3 and making it publicly accessible.

🧠 Why this matters

S3 allows hosting static websites cheaply and at scale without servers. It is commonly used in production with CloudFront. :contentReference[oaicite:0]{index=0}

🎥 Learn This Concept

▶ AWS S3 Static Website Hosting (Your Selected Tutorial)
  • Create S3 bucket
  • Upload files
  • Enable static hosting
  • Set permissions

🪜 Step 1 — Create S3 Bucket

  • Go to S3 service
  • Click "Create bucket"
  • Name: ai-ecosphere-frontend

⚠ Bucket name must be globally unique

🪜 Step 2 — Disable Block Public Access

  • Uncheck "Block all public access"
  • Acknowledge warning

⚠ Required to make website public

🪜 Step 3 — Upload Files

  • Upload your frontend files
  • Ensure file includes:
index.html
styles.css
(optional JS files)

🪜 Step 4 — Enable Static Hosting

  • Go to "Properties"
  • Scroll to "Static website hosting"
  • Enable it
  • Set:
Index document: index.html
Error document: index.html

🪜 Step 5 — Bucket Policy (CRITICAL)

Without this, your site will show Access Denied. 

{
 "Version": "2012-10-17",
 "Statement": [
  {
   "Effect": "Allow",
   "Principal": "*",
   "Action": "s3:GetObject",
   "Resource": "arn:aws:s3:::ai-ecosphere-frontend/*"
  }
 ]
}

🪜 Step 6 — Access Website

  • Go to "Properties"
  • Copy S3 website endpoint
http://your-bucket-name.s3-website-region.amazonaws.com

✔ Your frontend is live

⚙️ How this fits in system

User → S3 (Frontend) → API Gateway → EC2 → AI → Response

❌ Common Errors

  • Access Denied → missing bucket policy
  • Blank page → wrong index file
  • CSS not loading → wrong paths

🚦 Checklist

  • ✔ Files uploaded
  • ✔ Hosting enabled
  • ✔ Public access configured
  • ✔ Website opens in browser

✔ Frontend successfully deployed on AWS
