Step 5 — Auto Scaling (HPA)

🧠 Why this step?

More traffic → More CPU → More Pods

Horizontal Pod Autoscaler (HPA) automatically scales your application based on load.

🪜 Step 1 — Update deployment.yaml

Where

  • Open file: 
    aws-ai-ecosphere-prod/deployment.yaml

Add inside container section

resources:
  requests:
    cpu: "100m"
  limits:
    cpu: "500m"

These values allow Kubernetes to measure CPU usage.

🪜 Step 2 — Apply Changes

kubectl apply -f deployment.yaml

🪜 Step 3 — Install Metrics Server

kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml

🪜 Step 4 — Verify Metrics

kubectl top nodes

Expected

CPU usage visible

✔ Metrics working

🪜 Step 5 — Create HPA

kubectl autoscale deployment rag-app --cpu-percent=50 --min=2 --max=5

🪜 Step 6 — Check HPA

kubectl get hpa

Expected

rag-app   2/2   50%   2   5

🪜 Step 7 — Simulate Load

Where

  • Terminal
kubectl run load-test --image=busybox --restart=Never -- \
/bin/sh -c "while true; do wget -q -O- http://rag-service; done"

🪜 Step 8 — Observe Scaling

kubectl get pods -w

Expected

Pods increase as load increases

✔ Auto scaling working

🪜 Step 9 — Stop Load Test

kubectl delete pod load-test

🧠 What happened?

Load ↑ → CPU ↑ → HPA → More Pods → Stable system
