Step 7 — Persistent Storage (FAISS)

🧠 What problem are we solving?

Without storage:
Pod restart → FAISS data lost ❌

With storage:
Pod restart → Data persists ✅

We solve this using Kubernetes PVC backed by AWS EBS.

🧠 Key Concept

PVC → request for storage
PV → actual storage (EBS in AWS)

When you create a PVC, AWS automatically provisions an EBS volume.

🪜 Step 1 — Create pvc.yaml

Where: Your project folder (same as deployment.yaml)

apiVersion: v1 kind: PersistentVolumeClaim metadata: name: faiss-pvc spec: accessModes: - ReadWriteOnce resources: requests: storage: 5Gi

Run (local terminal):

kubectl apply -f pvc.yaml kubectl get pvc

Expected:

faiss-pvc Bound

✔ Storage allocated (EBS created)

🪜 Step 2 — Update deployment.yaml

Where: deployment.yaml file

BEFORE

containers: - name: rag-container image: rag-app

AFTER

containers: - name: rag-container image: rag-app volumeMounts: - mountPath: "/data" name: faiss-storage volumes: - name: faiss-storage persistentVolumeClaim: claimName: faiss-pvc

Apply:

kubectl apply -f deployment.yaml

🪜 Step 3 — Validate Volume Mount

kubectl get pods kubectl describe pod POD_NAME

Look for:

Mounts: /data

✔ Volume attached

🪜 Step 4 — Update Application Code

Where: app.py

faiss.write_index(index, "/data/faiss_index.bin")

If you skip this → data still gets lost

🪜 Step 5 — Validate Persistence

Run:

kubectl exec -it POD_NAME -- ls /data

Expected:

faiss_index.bin

✔ Data stored successfully

🪜 Step 6 — Restart Pod (IMPORTANT TEST)

kubectl delete pod POD_NAME kubectl get pods

After restart:

kubectl exec -it NEW_POD -- ls /data

✔ File still exists → persistence confirmed

🧠 If it does not work

  • PVC not bound:
    kubectl get pvc
  • No mount:
    kubectl describe pod
  • Wrong path: Check "/data" in code
